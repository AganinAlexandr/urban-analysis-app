# Анализ данных городской среды

Веб-приложение для анализа отзывов о городской среде с визуализацией на карте и аналитическими возможностями.

## 🎯 Текущий статус проекта

**MVP (Minimum Viable Product)** - приложение готово для базового использования с основным функционалом:
- ✅ Загрузка и обработка JSON файлов
- ✅ Автоматическое определение групп объектов
- ✅ Анализ сентиментов классическими методами
- ✅ Интерактивная карта с фильтрацией
- ✅ База данных SQLite с миграцией данных
- ✅ Система ключевых слов для определения групп
- ✅ Визуализация данных (таблицы, графики, тепловые карты)
- ✅ Кнопка очистки базы данных
- ✅ Ввод собственной оценки отзывов (Master Rating)

## 🗺️ Карта объектов

### Возможности карты:
- **Отображение объектов** - цветовая кодировка по группам
- **Интерактивные метки** - клик для просмотра детальной информации
- **Фильтрация по группам** - включение/выключение типов объектов
- **Автоматическое геокодирование** - определение координат по адресам
- **Кнопки управления** - групповые операции "Выбрать все", "Снять выбор" для групп

### Настройка карты:

1. **Получите API ключи:**
   - [Яндекс.Геокодер](https://developer.tech.yandex.ru/geocoder/) - для определения координат
   - [Яндекс.Карты](https://developer.tech.yandex.ru/maps/) - для отображения карты

2. **Для LLM анализа (опционально):**
   - [OpenAI](https://platform.openai.com/api-keys) - для GPT моделей
   - [Google AI Studio](https://makersuite.google.com/app/apikey) - для Gemini
   - [YandexGPT](https://cloud.yandex.ru/docs/foundation-models/operations/api-key) - для российских моделей
   - [GigaChat](https://developers.sber.ru/portal/products/gigachat) - для Сбера
   - [Qwen](https://dashscope.console.aliyun.com/) - для Alibaba
   - [DeepSeek](https://platform.deepseek.com/) - для DeepSeek

3. **Создайте файл .env:**
   ```bash
   cp env_example.txt .env
   ```

4. **Заполните API ключи в .env:**
   ```
   # Обязательные ключи
   YANDEX_GEOCODER_API_KEY=ваш_ключ_геокодера
   YANDEX_MAPS_API_KEY=ваш_ключ_карт
   
   # Опциональные ключи для LLM анализа
   OPENAI_API_KEY=ваш_ключ_openai
   GOOGLE_GEMINI_API_KEY=ваш_ключ_gemini
   YANDEXGPT_API_KEY=ваш_ключ_yandexgpt
   GIGACHAT_API_KEY=ваш_ключ_gigachat
   QWEN_API_KEY=ваш_ключ_qwen
   DEEPSEEK_API_KEY=ваш_ключ_deepseek
   ```

5. **Запустите приложение:**
   ```bash
   cd mvp_urban_analysis
   python app.py
   ```

- **Определение групп объектов** на основе ключевых слов

### Валидация данных
- Проверка обязательных полей
- Обработка безадресных отзывов
- Предотвращение дубликатов
- Автоматическое определение групп

### Архив данных

- Информация о заполненности полей
- Статистика по группам объектов
- Экспорт данных

## 🚀 Быстрый старт

### Требования
- Python 3.7+
- API ключи для геокодирования и карт
- API ключи для LLM - определение сентимента
- SQLite (встроен в Python)

### Установка
```bash
# Клонируйте репозиторий
git clone <repository-url>
cd mvp_urban_analysis

# Установите зависимости
pip install -r requirements.txt

# Настройте API ключи
cp env_example.txt .env
# Отредактируйте .env файл

# Запустите приложение
python app.py
```

### Использование
1. Откройте браузер: http://localhost:5000
2. Загрузите файл с данными (JSON)
3. При необходимости выберите группу для объектов
4. Выберите методы анализа:
   - **Классический анализ** - работает без дополнительных API ключей
   - **LLM анализ** - требует соответствующие API ключи в .env файле
5. Просмотрите результаты на карте и в таблицах
6. Используйте фильтры для анализа данных
7. При необходимости очистите базу данных через кнопку "Очистить БД"
8. Для отзывов используйте Master Rating для ввода собственных оценок

## 🐛 Устранение неполадок

### Карта не загружается
1. Проверьте API ключ Яндекс.Карт в .env
2. Убедитесь, что ключ активен в консоли разработчика
3. Проверьте консоль браузера на ошибки

### Геокодирование не работает
1. Проверьте API ключ Яндекс.Геокодера
2. Убедитесь, что адреса корректные
3. Проверьте лимиты API

### Ошибки загрузки файлов
1. Проверьте формат файла
2. Убедитесь, что обязательные поля присутствуют
3. Проверьте кодировку файла (UTF-8)

### Проблемы с определением групп
1. Проверьте содержимое JSON файла
2. Убедитесь, что в текстах есть ключевые слова для групп
3. При необходимости вручную выберите группу в модальном окне

### Проблемы с LLM анализом
1. **API ключи не работают:**
   - Проверьте правильность ключей в .env файле
   - Убедитесь, что ключи активны и не превышены лимиты
   - Проверьте баланс аккаунта для платных API

2. **LLM анализ недоступен:**
   - Убедитесь, что соответствующие API ключи добавлены в .env
   - Проверьте подключение к интернету
   - Проверьте логи приложения на наличие ошибок API

3. **Низкая точность LLM анализа:**
   - Попробуйте другую модель (например, YandexGPT для русского текста)
   - Проверьте качество входных данных
   - Убедитесь, что тексты достаточно длинные для анализа

## 🛠️ Правила разработки

### Принципы разработки
- **Всегда тестируйте функционал после изменений** - не полагайтесь на то, что "должно работать"
- **Делайте изменения пошагово** - проверяйте каждый шаг перед переходом к следующему
- **Используйте существующие паттерны кода** - не изобретайте новые без необходимости
- **При изменении функции сначала поймите** - как она используется в других местах проекта

### Правила именования
- **Переменные**: единственное число, camelCase, английский язык (`userName`, `objectCount`)
- **Функции**: глагол + существительное, camelCase (`getUserData`, `processFile`)
- **Константы**: UPPER_SNAKE_CASE (`MAX_FILE_SIZE`, `DEFAULT_TIMEOUT`)
- **Классы**: PascalCase, существительное (`DataProcessor`, `UserManager`)
- **Файлы**: snake_case, описательное название (`data_processor.py`, `user_manager.py`)

### Правила тестирования
- **После каждого изменения проверяйте основной функционал** - карта, загрузка файлов, фильтрация
- **Используйте console.log/print для диагностики** - добавляйте логи в ключевых местах
- **Тестируйте граничные случаи** - пустые значения, ошибки, некорректные данные
- **Проверяйте интеграцию между компонентами** - как изменения влияют на другие части системы

### Правила модульности
- **Изменения в одном модуле не должны влиять на другие** - соблюдайте принцип единственной ответственности
- **Используйте интерфейсы/контракты между модулями** - четко определите входы и выходы
- **Избегайте глобальных переменных** - передавайте данные через параметры функций
- **Функции должны иметь одну ответственность** - если функция делает много вещей, разбейте её

### Правила Git workflow
- **Делайте коммиты после каждого логического изменения** - не накапливайте много изменений в одном коммите
- **Используйте описательные сообщения коммитов** - "Fix: Снять выбор теперь корректно обновляет Таблицу БД"
- **Перед коммитом проверяйте, что код работает** - запустите приложение и протестируйте основные функции
- **Не коммитьте код, который не протестирован** - это может сломать работу других разработчиков

### Рекомендации по отладке
- **Начинайте с простых проверок** - убедитесь, что данные доходят до нужного места
- **Используйте системный подход** - проверяйте пошагово: фронтенд → API → бэкенд → база данных
- **Добавляйте временные логи** - для понимания потока выполнения
- **Проверяйте консоль браузера и терминал** - ошибки часто видны в логах
